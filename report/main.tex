\section{Introduction}

This project addresses the Briscola project.
Given a complete game as a folder of round videos, the system must infer the
cards played by both players, the leader, the briscola card, the winner and
points of each round, and the final game result. The provided ground-truth CSV
files are used to evaluate these predictions.

Our work focuses on comparing alternative computer-vision pipelines while
keeping game orchestration, Briscola rules, output, and evaluation shared.

\section{Shared architecture}

The visual method can change, while Briscola rules, scoring, video order, CSV
output, and evaluation stay the same. We keep these parts separate so that a
vision pipeline only produces evidence, while the shared game code calculates
the round outcomes and final result. In this way, every pipeline uses the same
game rules and can be compared fairly.

An \texttt{IRoundAnalyzer} reads a round video and returns a
\texttt{RoundObservation}, while \texttt{GameRunner} orders the videos, gives
each round its number, and collects the observations. The fields in
\texttt{RoundObservation} are optional because a card can be covered, blurred,
or missed by the detector. Rather than forcing a guess, the system leaves that
value empty and calculates an outcome only when it knows both cards, the
leader, and the briscola. This stops a weak vision result from silently
changing the game score.

The briscola is handled by a separate \texttt{IBriscolaProvider} because it
belongs to the whole game, not to one round. Depending on the pipeline, it can
be found from one frame, from round candidates, or by voting across the game.
This choice does not affect the round analyzer, while the shared debugging and
evaluation make the different choices easy to compare.

\section{Vision pipelines}

\subsection{YOLO and local-feature pipeline}

\subsubsection{Overview}

This pipeline has two steps: a one-class YOLO oriented-bounding-box model first
finds physical cards, then local features identify each one by comparing it
with the 40 reference scans. We did not train YOLO to recognise 40 classes.
Instead, it only learns the shape of a card, while the reference scans handle
the card identity. This makes the detector and classifier easier to improve
separately.

    \caption{Debug output on a difficult frame. Even with a hand covering part
    of the cards, the pipeline detects and classifies the visible face-up cards.}
    \label{fig:yolo-orb-pipeline}
\end{figure}

\subsubsection{Detector training}

We fine-tuned a pretrained YOLO OBB model on a synthetic one-class dataset,
because we did not have enough labelled video frames to train directly on them.
Card scans let us generate many different scenes. Each image contains 1--6
face-up cards on a DTD texture background, with changes in position, size,
rotation, perspective, overlap, and edge cropping. We also add brightness and
contrast changes, blur, and noise. Some backgrounds are scaled down to include
fine checked textures like those in the real tablecloth.

Card backs are added as unlabelled distractors. Although they look like cards,
they cannot be used in the game, so they are not ground truth. Including them
helps the detector avoid treating every card-like object as a useful face-up
card.

We use oriented boxes instead of normal axis-aligned boxes because we need the
four corners for perspective rectification. A card needs at least 30\% of its
area visible to be labelled, but its label still covers the whole physical card
when part of it is hidden. This gives a stable shape for rectification when
cards overlap or are cropped.

\subsubsection{Card classification}

We warp each oriented box to the same shape as the reference scans, 581
$\times$ 315 pixels, and test both the crop and its 180-degree rotation so that
upside-down cards can still match. The reference keypoints and descriptors are
computed once when the application starts, then each crop is compared with all
40 references.

At first, we used SIFT, but it caused a clear problem with the coins suit. The
same coin symbol appears at different sizes and positions on several cards, so
SIFT could match a large coin on one card with a smaller coin on another one.
Since rectification already gives us the expected size and orientation, we do
not need SIFT's scale invariance. The final method therefore uses one-level ORB
with Hamming distance, which has no scale pyramid and is much faster.

We use OpenCV's brute-force matcher, Lowe's ratio test, and a 60-pixel spatial
mask. The mask accepts a pair only when the two features are in similar places
on the normalised crop and reference. Since local features alone do not know
the full card layout, this reduces wrong matches between repeated symbols. We
also use OpenCV's matcher instead of our own distance loop because it runs the
same brute-force search much faster.

\subsubsection{Temporal aggregation}

One frame is not enough to decide a round because a card can be missed,
misclassified, or almost fully covered. We first tried to use a frame with two
vertical player-card boxes, but this failed when the second card covered the
first one: the cards were seen at different times, but never together.

The final method groups vertical detections by their predicted card over the
whole round and chooses the two stable card classes that appear most often.
Their median vertical position gives North and South, while the class that
appears stably first gives the leader. In this way, the method uses evidence
from the full video instead of relying on a single good frame.

A frame with exactly one horizontal card gives one vote for the briscola, and
the most frequent candidate from all rounds becomes the game briscola. One
wrong detection or classification therefore cannot decide the game. This method
uses some assumptions about this dataset: the briscola is horizontal and always
visible, while player cards are vertical and stay in upper and lower areas.
These are not Briscola rules, and other analyzers do not need to use them.

\subsubsection{Current configuration and limitation}

The final configuration uses 0.60 detector confidence, one-level ORB with
5,000 keypoints, and the 60-pixel spatial mask. We kept the high number of
keypoints because it improved card recognition, even though it makes the
pipeline slow. Every crop and its rotated version are matched with all 40
references, so feature extraction, mask creation, and brute-force matching take
most of the time. The pipeline is not real-time, but real-time use is not the
goal of this project.


\subsection{K-Means and Bag-of-Visual-Words pipeline}

\subsubsection{Overview}

This pipeline explores how far a fully classical, non-neural detector and
classifier can go on the same task. The goal was not to beat YOLO/local-features
accuracy, but to map the boundary of a bag-of-visual-words classifier when
the card is lying on a checked tablecloth, often partially covered by another
card. The detector is a K-Means segmentation followed by a geometric filter; the
classifier is a BoW vocabulary built from SIFT descriptors of the 40 reference
scans. The pipeline is fully deterministic (k-means is seeded at 42) and
requires no training data, no GPU, and no learned model.

\subsection{K-Means and Bag-of-Visual-Words pipeline (PINTON MATTIA)}

\subsubsection{Overview}

This pipeline explores how far a fully classical, non-neural detector and
classifier can go on the same task. The goal was not to beat YOLO/local-features
on accuracy, but to map the boundary of a bag-of-visual-words classifier when
the card is lying on a checked tablecloth, often partially covered by another
card. The detector is a K-Means segmentation followed by heavy morphological
operations and a strict geometric filter; the classifier is a BoW vocabulary built
from SIFT descriptors of the 40 reference scans. The pipeline is fully deterministic
(k-means is seeded at 42) and requires no training data, no GPU, and no learned model.

\subsubsection{Detector: K-Means plus local variance}

The detector has to solve one specific problem: the card face and the light
squares of the tablecloth have nearly the same colour, so a plain K-Means on
the raw frame merges them. The pipeline therefore applies, before any
clustering, a Gaussian blur ($81\times81$) whose kernel is larger than one
checkerboard period. When the kernel spans at least one full light/dark cycle,
every output pixel is an average of several light and dark squares, and the
tablecloth collapses to a mid-gray while the card face survives almost unchanged.

The blur alone is not enough when the kernel is not perfectly matched to the
pattern. A local variance map is therefore computed on the blurred grayscale
frame with two box filters ($\mathrm{Var} = E[I^2] - E[I]^2$). The card face,
being spatially uniform, has near-zero variance; the residual checkerboard has
high variance. A threshold on this map produces a \emph{uniform mask} that
removes the surviving fragments of the tablecloth before connected components
see them.

K-Means is then run on the blurred colour frame with $K=6$; the table is
modelled by the largest clusters, and the brightest foreground cluster is taken
as the card face. To recover fragmented regions caused by card figures, the mask
undergoes mass morphological operations (heavy dilation followed by erosion).
The largest blob is evaluated on five geometric properties, and its total combined
score must pass a strict global threshold ($\ge 2.1$) to ensure the blob is an actual
card and not a false positive like a player's hand or a shadow. The oriented
bounding box (\texttt{minAreaRect}) is computed and then padded mathematically
by 8\% to capture the physical card edges and provide a robust, context-rich crop
for the classifier.

\subsubsection{Recognition: Bag of Visual Words}

A vocabulary of $K=800$ visual words is built by running k-means over SIFT
descriptors extracted from the 40 reference cards and their augmented
variants. The augmentation covers rotations (including 180$^\circ$ for upside-down cards),
illumination changes, scaling, blur, and partial occlusions. The occlusions
are produced by cropping the card to a fraction of its area (40\%--90\% visible,
centered), which reproduces the actual geometry of the detector's output.

Each variant produces one reference histogram of size K. At query time, the
crop is aligned to the axes using the rotated rect, SIFT descriptors are extracted,
the query histogram is built, and the best match is chosen by chi-square distance
over all reference histograms in a single, highly efficient pass (since the
vocabulary is already rotation-aware).

\subsubsection{Pipeline integration}

\texttt{KMeansBriscolaProvider::find} scans up to 60 frames per round, calls
\texttt{findBBox} on each, and on the first successful detection classifies the
aligned crop. The provider implements \texttt{IBriscolaProvider}, so it can be
plugged into the existing \texttt{GameRunner} without changes to the rules or
the I/O.

The BoW classifier also replaces the built-in template matcher inside the
movement-pattern analyzer (\texttt{KMeansBowRoundAnalyzer}), via the \texttt{--bow} flag.
Because the frames selected by the movement analyzer contain multiple cards
(the briscola and the played cards), \texttt{findBBox} is guided by a
\textbf{Dynamic Temporal Mask}. By computing the absolute difference (\texttt{absdiff})
between a reference background frame (just before the player moves) and the
action frame, the pipeline isolates the exact region of new movement. K-Means
only searches inside this motion window, effortlessly ignoring the briscola and
any overlapping previously played cards. To ensure stability against transient
noise (e.g., a lingering hand), the pipeline uses a \textbf{Multi-frame Search Window},
scanning up to 5 consecutive frames and locking onto the first geometrically
perfect card.

\subsubsection{Results and limitations}

The briscola card was recovered correctly on all four provided games. The
played-card classification is around 40\% - 45\% across the four games.

The failure is systematic and comes from the BoW method. A
card whose visible face shows fewer symbols than the real card (four denari
visible on a six-coins, five spade tips visible on a four-spades) is
misclassified toward the visually present rank, because the histogram loses
the descriptors of the covered symbols and the nearest reference becomes a
different card that happens to share the visible pattern. SIFT, which matches
descriptors locally and uses geometric verification, does not suffer from
this failure mode and is the recommended method when occlusion is expected.
Estimated number of hours for the implemnetation: 50 hours. 


\subsection{Movement Pattern pipeline}
The Movement Pattern pipeline, along with the standalone applications
\texttt{movement\_pattern} and \texttt{evaluate\_}\allowbreak\texttt{movement\_pattern},
was conceived, designed, developed, tested, and performance-optimized
independently by Martina Naldoni.
It was designed with the goal of achieving high computational efficiency,
identifying the approximate positions of the cards through temporal frame differencing
in order to inspect the minimum number of frames required.

\subsubsection{First-frame briscola provider}
For the briscola provider, card localization is achieved by differencing the
first frame of specific rounds. In round 1, frame 0, there is only the briscola
and the draw deck on top of it, alongside the background. In the first frame of
an endgame round (we chose round 17), there are the trick decks of cards won by
each player, the briscola and remaining deck, and the background. In the last
round (round 20), the briscola and draw deck are no longer there, leaving only
the background and each player's won cards. Turning this into an equation:
\begin{align}
    I_{\text{briscola}} &= (I_{\text{player decks}} + I_{\text{bg}} + I_{\text{briscola}}) - (I_{\text{player decks}} + I_{\text{bg}}) \nonumber \\
    &= \left| I_{\text{round 17, frame 0}} - I_{\text{round 20, frame 0}} \right|
\end{align}
This differencing is paired with blob detection because smaller differences in
illumination might produce minor false positive returns. It isolates an
accurate, small region of interest (a $500 \times 500$ window around the
detected centroid on round 1, frame 0) to compare with the 40 reference card
templates. Comparing features only within this cropped window rather than the
entire frame reduced matching time from $\sim 15$ seconds to $1.3$ seconds. The
card prediction is obtained using SIFT by computing the keypoints of each
template and comparing them to those of the extracted window with a simple
most-matches-win technique.

\subsubsection{Movement pattern round analyzer}
For the round analyzer, to achieve an efficient analysis it was essential to
evaluate the least possible number of frames. The 2 played cards are accurately
located by evaluating only 3 frames per round. To determine which frames to
analyze, the movement between consecutive frames is computed as the number of
pixels with significant intensity changes:
\begin{equation}
    M(t) = \sum_{(x,y)} \mathbb{I}\left( \left| I_t(x,y) - I_{t-1}(x,y) \right| > \tau \right)
\end{equation}
The movement is treated as a continuous signal $M(t)$, whose derivative
$\frac{dM}{dt}$ is computed (after Gaussian smoothing) to locate local peaks and
troughs. Observing the movement graph reveals a characteristic kinematic pattern:
to insert a new card, the hand comes into the frame (movement local peak),
positions the card on the table (movement local low), and then retracts (movement
local peak). After it has retracted, there is a low that reaches near 0, or 0,
when the other player evaluates the card that was just played. This pattern then
repeats for the second card played. This allows us to find frames where, with
high confidence, only cards and background are present without hands.

This logic is challenged in game 3, where the author's grandmother leaves her
hand in the frame after placing the card, or does not wait to place the second
card and collects the cards in one single continuous move. Nevertheless, cards
and round leaders are still detected this way.

The near-0 movement lows after each pattern are when we decide to extract the
frames to analyze:
\begin{align}
    \Delta I_{\text{first card}} &= (I_{\text{bg}} + I_{\text{briscola}} + I_{\text{card}_1}) - (I_{\text{bg}} + I_{\text{briscola}}) \nonumber \\
    &= \left| I_{\text{frame after first pattern}} - I_{\text{frame 0}} \right| \\[6pt]
    \Delta I_{\text{second card}} &= (I_{\text{bg}} + I_{\text{briscola}} + I_{\text{card}_1} + I_{\text{card}_2}) \nonumber \\
    &\quad - (I_{\text{bg}} + I_{\text{briscola}} + I_{\text{card}_1}) \nonumber \\
    &= \left| I_{\text{frame after second pattern}} - I_{\text{frame after first pattern}} \right|
\end{align}
As before, blob detection filters out minor false positives, refines the
bounding box around the card as closely as possible, and passes it to an ORB
classifier. The classifier precomputes the features of the 40 template cards at
application startup and caches them in memory, comparing them to the descriptors
of the bounding box to assign the card prediction via nearest match inliers.

\paragraph{Leader Identification via First Motion.}
The leading player is recognized directly by checking where the very first
movement in the frame appears. When the motion curve reaches its first entry
peak ($P_{1a}$), the camera frame is partitioned into an upper region
($Y \in [0, 0.65H]$) and a lower region ($Y \in [0.35H, H]$). The analyzer
evaluates the number of thresholded moving pixels in both halves:
\begin{equation}
    \text{Leader} =
    \begin{cases}
        \text{North} & \text{if } M_{\text{top}}(P_{1a}) \ge M_{\text{bottom}}(P_{1a}) \\
        \text{South} & \text{otherwise}
    \end{cases}
\end{equation}
Because the kinematic curve isolates the exact frame where the first hand
enters the field of view before the card is deposited, this spatial motion check
is exceptionally robust against subsequent card overlap or hand withdrawal,
achieving 98.8\% accuracy on Mac and a perfect \textbf{100.0\% (80/80 rounds)}
on the VLab server.

    table at the end of the round.
\end{itemize}

    \begin{itemize}

    \item \textbf{Personal Laptop (MacBook with Apple Silicon M1 processor)}:
    \begin{itemize}
        \item Preprocessing (reference feature caching): 2 seconds
        \item Game 1: 32''
        \item Game 2: 25''
        \item Game 3: 23''
        \item Game 4: 28''
        \item Total runtime across all 4 games: 1' 48'' ($\approx 27''$ average per 20-round game)
    \end{itemize}
\end{itemize}
Compared to the YOLO pipeline which requires 28--34 minutes per game on CPU,
the Movement Pattern pipeline achieves a $\approx 20\times$ speedup on the x86-64
Vlab server and over a $60\times$ speedup on the M1 MacBook.

Across the four games, the YOLO + ORB pipeline correctly predicted 158 of 160 player
cards, all 160 leader/winner fields, three of four briscola cards, and all 12
final-game-result fields. The only briscola error had the correct suit but the
wrong rank; it therefore did not affect any round winner, score, or final game
result.

The Movement Pattern pipeline presents an exceptionally compelling speed-accuracy
trade-off. By leveraging temporal motion differencing to inspect only 2--3 critical
frames per round, it eliminates the immense computational burden of frame-by-frame
deep-learning inference, finishing all 20 rounds of a game in just 25--30 seconds on
the M1 MacBook (and under 1'30'' on Vlab). Across the four benchmark games, it
achieves 100\% Briscola recognition, 98.8\%--100\% leader accuracy, and
86.9\%--88.1\% overall card accuracy. Under standard playing tempo (Game 4), its
accuracy reaches a flawless 100\% across all categories. Its primary failure mode
occurs in Game 3, where a player's hand lingers on the table, perturbing the
stationary frame differencing.

The K-Means + BoW pipeline successfully solves the static tablecloth segmentation
and identifies Briscola cards on all games (100\%), but struggles with partial
occlusion on played cards (42.5\% accuracy), as visual word histograms fail to
differentiate partially covered cards that share dominant repeating symbols.

The empirical comparison reveals notable cross-platform consistency alongside
subtle architecture-specific traits:
\begin{itemize}
    \item \textbf{Briscola and Game 4 stability:} The Briscola provider achieves
    a perfect 100\% (4/4 games) on both platforms. Similarly, Game 4 exhibits
    flawless 100\% accuracy across all 40 cards, 20 leaders, and 3 game result
    fields in both environments.
    \item \textbf{Virtual Lab perfection on Game 2 and Leaders:} In the VLab
    environment, Game 2 achieves a perfect 40/40 (100.0\%) card recognition score,
    and the round leader is correctly identified across all 80 rounds (100.0\%),
    yielding an overall card recognition rate of 88.1\% (141/160).
    \item \textbf{Origin of variations:} The slight variance on borderline rounds
    (e.g., Game 1 South card 11, Game 2 North card 1) stems from low-level
    floating-point arithmetic differences in OpenCV between ARM NEON vector
    primitives (Apple Silicon) and x86-64 AVX/SSE instructions (VLab). Minor
    rounding variations during Gaussian filtering and affine rectification subtly
    shift sub-pixel keypoint coordinates and ORB descriptor angles near the
    inlier threshold boundary.
    \item \textbf{Execution throughput:} The Apple M1 processor benefits from
    fast unified memory, processing an entire 20-round game in $\approx 27$
    seconds, while the shared VLab virtualized CPU completes a game in
    $\approx 1'$ 28''. Both platforms run faster than real-time video playback
    (which lasts $\sim 2$--$3$ minutes per game) and represent a vast speedup over
    the 28--34 minutes per game required by YOLO.
\end{itemize}

\section{Conclusion}

In this project, we developed and compared multiple computer vision approaches
to automated Briscola game analysis: a deep-learning oriented detector (YOLO + ORB),
an ultra-fast kinematics-driven method (Movement Pattern), and a classical
appearance-based method (K-Means + Bag of Words).

Our shared architecture allows the user to choose the path that best suits their
specific needs, whether their priority is maximum precision or high execution
speed. Users who demand the highest classification accuracy across difficult
occlusions can select the YOLO pipeline, while users who need near-instantaneous
results on everyday hardware (processing an entire 20-round game in under half a
minute with over 86\%--88\% accuracy and 100\% Briscola recognition) can choose
the Movement Pattern pipeline. We believe that this flexibility—offering clear
trade-offs between computational cost and accuracy—is what makes our project
especially versatile and complete.
